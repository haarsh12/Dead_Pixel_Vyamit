================================================================================
ISSUE 1: GET /items/ → 403 Forbidden
================================================================================

CAUSE:
------
The endpoint requires authentication and returns 403 when:
- User token is invalid or expired
- User account is inactive (is_active = False)
- User not found in database

CODE LOCATION:
--------------
File: backend_app/api/items.py
Function: _active_inventory_scope()

Lines 35-41:
    user = session.get(User, user_id)
    if user is None or not user.is_active:
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Account is unavailable",
        )

SOLUTION:
---------
✅ Check user authentication token
✅ Verify user account is active
✅ Re-login if token expired

HOW TO FIX:
1. User should login again to get fresh token
2. Check if user account is active in database
3. Verify token is being sent in Authorization header:
   Authorization: Bearer <token>

================================================================================
ISSUE 2: POST /auth/send-otp → 404 Not Found
================================================================================

CAUSE:
------
Possible causes:
1. Trailing slash mismatch (/auth/send-otp vs /auth/send-otp/)
2. Server not running
3. Wrong base URL

CODE LOCATION:
--------------
File: backend_app/api/auth.py
Line 45: @router.post("/send-otp", status_code=status.HTTP_200_OK)

Registered in main.py:
Line 88: app.include_router(auth.router, prefix="/auth", tags=["Authentication"])

Expected URL: POST http://localhost:8000/auth/send-otp

SOLUTION:
---------
✅ Use correct URL without trailing slash
✅ Verify server is running
✅ Check CORS settings if calling from Flutter app

HOW TO FIX:
1. Ensure URL is: POST /auth/send-otp (no trailing slash)
2. Check server logs for route registration
3. Test in browser: http://localhost:8000/docs

================================================================================
ISSUE 3: POST /auth/send-otp → 422 Unprocessable Entity
================================================================================

CAUSE:
------
Request body doesn't match the required schema.

REQUIRED SCHEMA:
----------------
{
  "phone_number": "string",  // 10-15 chars, valid Indian number
  "is_login": boolean        // default: true
}

VALIDATION RULES:
-----------------
1. phone_number must be 10-15 characters
2. Must be valid Indian mobile number (starts with 6-9, 10 digits)
3. Formats accepted:
   - "9876543210"
   - "+919876543210"
   - "919876543210"
4. Invalid formats:
   - "123" (too short)
   - "1234567890" (doesn't start with 6-9)
   - "abc1234567" (contains letters)

CODE LOCATION:
--------------
File: backend_app/db/schemas.py
Lines 17-29: OTPRequest schema with validation

COMMON MISTAKES:
----------------
❌ Missing phone_number field
❌ Phone number too short (< 10 digits)
❌ Invalid Indian number (doesn't start with 6-9)
❌ Special characters in phone number
❌ Missing required fields

SOLUTION:
---------
✅ Send valid phone number
✅ Include is_login field
✅ Use proper JSON format

VALID EXAMPLES:
---------------
Example 1 (Login):
{
  "phone_number": "9876543210",
  "is_login": true
}

Example 2 (Register):
{
  "phone_number": "+919876543210",
  "is_login": false
}

Example 3 (With country code):
{
  "phone_number": "919876543210",
  "is_login": false
}

INVALID EXAMPLES:
-----------------
❌ {
  "phone_number": "123",
  "is_login": true
}
Error: Phone number too short

❌ {
  "phone_number": "1234567890",
  "is_login": true
}
Error: Must start with 6-9 (valid Indian mobile)

❌ {
  "phone": "9876543210",
  "is_login": true
}
Error: Field name must be "phone_number" not "phone"
